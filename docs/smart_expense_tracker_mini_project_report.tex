% --- Abstract ---
\section*{ABSTRACT}
\addcontentsline{toc}{section}{ABSTRACT}
Smart Expense Tracker is a secure, web-based financial management system designed to empower users with real-time control over their personal economy. Built on a robust \textbf{Modified MVC (Model-View-Controller)} architecture, the system leverages \textbf{Python (Flask)} and \textbf{MySQL} to provide high-integrity data management and visual analytics. 

The application facilitates precise income and expense tracking, category-specific monthly budgeting with automated alert thresholds, and milestone-based savings goal management. Featuring a premium, responsive interface styled with \textbf{Tailwind CSS}, it transforms raw transaction data into actionable financial insights. By industrializing the traditional ledger through automated balance invariants and secure session-based authentication, the project ensures data persistence, privacy, and proactive financial monitoring.

% --- Chapter 1 ---
\section{INTRODUCTION}
Effective financial literacy begins with the accurate recording of every transaction. The Smart Expense Tracker addresses the modern need for a centralized, secure, and intuitive platform to manage personal finances.

\subsection{BACKGROUND}
The current manual methods of financial tracking suffer from lack of real-time accessibility, high error rates, and zero proactive monitoring. Physical ledgers provide no security and are time-consuming to audit. The Smart Expense Tracker solves these by internalizing business logic that automatically calculates available balances based on earnings, expenditures, and pre-allocated savings.

\subsection{SCOPE}
The project is designed for individual users seeking to manage high-frequency daily transactions. It covers identity security, financial enforcement via budget alerts, and dynamic reporting.

\subsection{OBJECTIVE}
The main objective is to provide an automated alternative to error-prone manual bookkeeping while implementing a \textbf{Service-Repository} architecture for decoupled, maintainable code.

\subsection{PROPOSED SYSTEM}
The Smart Expense Tracker utilizes a modern technical stack to ensure scalability. It introduces a "virtual allocation" logic for savings where allocated funds are treated as "reserved," dynamically reducing the `Available Balance` shown on the dashboard to prevent accidental overspending.

% --- Chapter 2 ---
\section{SOFTWARE REQUIREMENT SPECIFICATION (SRS)}
This chapter provides a technical breakdown of the product specification.

\subsection{PRODUCT OVERVIEW}
A full-stack web application implementing the \textbf{Modified MVC} pattern. The backend handles transaction processing and budget validation, while the frontend handles asynchronous data submission and dynamic charting.

\subsection{PRODUCT FUNCTIONALITY}
\textbf{User Features:}
\begin{itemize}
    \item \textbf{Onboarding}: Registration and login using \textbf{Bcrypt} hashing.
    \item \textbf{Transaction Engine}: CRUD operations with automatic category detection.
    \item \textbf{Budgeting}: Set monthly limits with 80\% and 100\% threshold notifications.
    \item \textbf{Goal Management}: Track savings with automated system-audit transactions.
\end{itemize}

\subsection{DESIGN AND IMPLEMENTATION CONSTRAINTS}
Constraints include data isolation via unique user IDs, row-level locking during sensitive financial updates, and custom JSON serialization for accurate handling of \textbf{Decimal} types.

\subsection{HARDWARE REQUIREMENTS}
\begin{itemize}
    \item \textbf{Processor}: Dual-core 2.4 GHz.
    \item \textbf{RAM}: 4 GB (Server-side) / 2 GB (Client-side).
\end{itemize}

\subsection{SOFTWARE REQUIREMENTS}
\begin{itemize}
    \item \textbf{Runtime}: Python 3.9+, Flask 2.0+
    \item \textbf{Libraries}: Flask-Login, Flask-Bcrypt, mysql-connector-python.
    \item \textbf{Frontend}: Tailwind CSS 3.0+, Chart.js.
    \item \textbf{Database}: MySQL 8.0+ (InnoDB Engine).
\end{itemize}

% --- Chapter 3 ---
\section{MATERIAL AND METHODS}
The development process prioritized the \textbf{separation of concerns}.

\subsection{DESIGN PHASE (Service-Repository Pattern)}
Logic is split into Routes, Services (containing business rules like budget alerts), Repositories (raw SQL), and Models (data structure).

\subsection{DATA FLOW DIAGRAM (DFD)}
The internal calculation flow follows the formula: \textbf{Available Balance = Total Income - (Expenses + Allocated Savings)}. This ensures that "Available Balance" accurately represents spending power after accounting for future goals.

\subsection{DATABASE DESIGN}
The database uses a strictly relational schema (InnoDB) to ensure data consistency. The \textbf{users} table serves as the anchor for all financial history, ensuring that account deletion triggers a cascading purge of related data.

\section{RESULTS AND DISCUSSION}

The integration of a \textbf{Custom JSON Provider} resolved floating-point inaccuracies typical in JavaScript, ensuring all financial data is precise to two decimal places.
