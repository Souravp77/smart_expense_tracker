📌 Key Dataflow Scenarios

🔐 User Login Flow

1
User enters email + password on login.html
2
Browser POSTs form data to /login
3
auth_bp.login() receives POST, calls get_user_by_email()
4
User.find_by_email() queries users table
5
Bcrypt verifies password_hash
6
login_user(user) sets session cookie; redirects to /dashboard
7
dashboard.html loads; JS calls GET /api/data
8
MySQL returns transactions + goals; Chart.js renders

📝 Registration Flow

1
User fills register.html form
2
auth_bp.register() checks email uniqueness
3
Bcrypt hashes password; register_user() INSERTs into users
4
seed_demo_data(user_id) inserts sample transactions & goals
5
MySQL stores new user + demo data, returns new user_id
6
Flash success → redirect to /login

💸 Add Transaction Flow

1
User fills Add Transaction modal in dashboard
2
JS sends POST /api/transactions with JSON payload
3
create_transaction(): validates payload via validate_transaction_payload()
4
add_transaction(user_id, data) INSERTs into transactions
5
If goal_id set → UPDATEs savings_goals.current_amount
6
MySQL commits; returns new transaction_id
7
JS receives 201 Created → updates UI state

🎯 Savings Goal Flow

1
User creates / edits goal in Savings tab
2
JS sends POST /api/goals with name, target, current, color
3
create_goal() validates + calls add_goal(user_id, data)
4
goal_service INSERTs row into savings_goals
5
MySQL stores goal; any future transaction linking this goal auto-increments current_amount
6
Progress bar re-renders based on current_amount / target_amount

📊 Dashboard Data Load

1
On page load JS calls GET /api/data
2
@login_required verifies session; get_data() called
3
get_dashboard_payload(current_user) queries transactions + goals
4
MySQL returns all rows for user_id
5
Service serialises dates/Decimals → JSON dict
6
JS renders charts (Chart.js) + transaction table + KPI cards

⚙️ Settings Update Flow

1
User changes username / currency in Settings tab
2
JS sends POST /api/settings with JSON
3
save_settings() validates; calls update_settings(user_id, payload)
4
settings_service UPDATEs users table
5
current_user.currency updated in-session (no reload needed)
6
JS receives 200 OK → displays updated currency symbol
